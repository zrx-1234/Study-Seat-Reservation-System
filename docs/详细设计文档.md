## 2. 分层架构概述

系统采用 **分层架构 + 领域驱动设计**，各层职责明确：

| 层级 | 职责 | 模块示例 |
|-----|------|---------|
| 接口层（API Layer） | REST接口暴露、参数解析、鉴权、响应序列化 | api/student.py, api/admin.py |
| 领域层（Domain Layer） | 核心业务逻辑、领域服务、领域模型 | domain/user/service.py |
| 基础设施层（Infrastructure） | 技术能力提供、数据库访问、认证缓存等 | infrastructure/auth.py |

### 2.1 架构约束

1. **只能上层依赖下层**: API层 → 领域层 → 基础设施层
2. **领域模块单向依赖**: 避免循环依赖，模块间通过Service接口交互
3. **接口层无业务逻辑**: 只负责协议适配，业务逻辑下沉到领域层
4. **基础设施不依赖业务**: 保持技术无关性

## 3. 基础设施层模块设计

### 3.1 INF-EXC: 异常与响应模块

**文件位置**: `infrastructure/exceptions.py`

#### 3.1.1 功能描述

提供统一的响应格式、领域异常基类以及全局异常处理器，确保整个系统的API响应格式一致，错误处理标准化。

#### 3.1.2 核心组件

| 组件 | 类型 | 描述 |
|-----|-----|------|
| `success_response()` | 函数 | 统一成功响应格式 |
| `error_response()` | 函数 | 统一错误响应格式 |
| `DomainException` | 异常基类 | 所有业务异常的基类 |
| `AuthenticationError` | 异常类 | 认证失败异常（401） |
| `AuthorizationError` | 异常类 | 权限不足异常（403） |
| `NotFoundError` | 异常类 | 资源不存在异常（404） |
| `ConflictError` | 异常类 | 资源冲突异常（409） |
| `ValidationError` | 异常类 | 参数验证异常（400） |
| `register_error_handlers(app)` | 函数 | 注册全局异常处理器到Flask应用 |

#### 3.1.3 统一响应格式

```json
{
    "code": 200,
    "message": "success",
    "data": {}
}
```

#### 3.1.4 被依赖模块

- 所有API层模块
- 所有领域层模块

### 3.2 INF-AUTH: 认证与权限模块

#### 3.2.2 核心函数

|-------|-----|-------|------|
| `hash_password()` | password: str | str | 密码哈希 |
| `verify_password()` | password_hash: str<br>password: str | bool | 验证密码是否正确 |
| `create_token()` | identity: str<br>additional_claims: dict | str | 创建JWT访问令牌 |
| `get_current_user_id()` | 无 | int | 获取当前登录用户ID（从JWT解析） |
| `get_jwt_claims()` | 无 | dict | 获取JWT的全部Claims |
| `require_permission()` | permission_code: str | 装饰器 | RBAC权限装饰器 |
| `register_jwt_callbacks()` | jwt_instance: JWTManager | 无 | 注册JWT错误回调 |

#### 3.2.3 被依赖模块

- api/student.py
- api/admin.py
- api/ai.py
- domain/user/service.py

### 4.3 MOD-RESV: 预约与签到模块

**文件位置**: `domain/reservation/`

#### 4.3.1 功能描述

负责预约的生命周期管理（提交、取消、完成）、时间冲突检测、签到校验、违约判定、违约记录管理、定时任务触发等功能。是系统的核心业务模块。

#### 4.3.2 数据模型

| 模型 | 表名 | 描述 |
|-----|------|------|
| `Reservation` | reservation | 预约记录表 |
| `ViolationRecord` | violation_record | 违约记录表 |

#### 4.3.3 Service API 定义

```python
# domain/reservation/service.py

# ========== 预约生命周期 ==========
def create_reservation(user_id: int, seat_id: int,
                       start_time: datetime, end_time: datetime) -> dict:
    """
    提交座位预约
    内部校验规则：
      1. 起止时间必须为整点小时
      2. 单次预约时长 <= system.get_config('max_reservation_hours')
      3. 用户进行中预约数 < system.get_config('max_active_reservations')
      4. 目标时间段内无冲突预约
      5. 座位状态为 available
      6. 预约时间段在自习室开放时间内
    预约成功后，返回完整的预约信息
    副作用：可触发 MOD-NOTIF.send_notification() 发送预约成功通知（异步）
    """

def create_reservation_on_behalf(admin_id: int, target_username: str,
                                 seat_id: int, start_time: datetime,
                                 end_time: datetime) -> dict:
    """
    管理员代理预约（为学生预约座位）
```

### 4.6 MOD-AI: 智能助手模块

**文件位置**: `domain/ai/`

#### 4.6.1 功能描述

负责自然语言意图识别、多轮对话状态管理、大语言模型调用、结构化回复生成。本模块不持有独立业务数据，通过调用其他领域模块的Service接口获取数据。

#### 4.6.2 Service API 定义

```python
# domain/ai/service.py

def chat(user_id: int, message: str, session_id: str = None) -> dict:
    """
    智能助手主入口
    执行流程：
      1. 获取或创建会话上下文（session_id）
      2. 调用 parse_intent() 解析用户意图
      3. 根据意图类型，调用对应领域模块获取数据
         - query_empty_seat: MOD-ROOM.search_seats()
         - query_my_reservation: MOD-RESV.get_user_active_reservations()
         - query_room_info: MOD-ROOM.list_rooms()
      4. 将数据组装为自然语言回复（本地模板或LLM生成）
      5. 返回结构化响应（含 reply、action、payload）
    """

def get_session_history(session_id: str) -> List[dict]:
    """
    获取指定会话的历史消息列表（最近N条，建议保留10-20条上下文）
    """

def clear_session(session_id: str) -> None:
    """
    清除指定会话的历史记录
    """

# ========== 内部核心函数（不对外暴露给非AI模块） ==========
def parse_intent(message: str, context: dict) -> dict:
    """
    解析用户自然语言消息，识别意图与提取槽位
    实现策略（可分层）：
      Level 1: 关键词匹配（保底方案，无需外部依赖）
      Level 2: 大语言模型+Prompt Engineering（提升体验）
    返回意图类型、置信度、提取参数（如日期、偏好条件）
    """

def execute_intent(intent: dict, user_id: int) -> dict:
    """
    根据解析后的意图，调用对应领域模块执行查询或操作
    返回查询结果或操作状态
    """

def generate_reply(action_result: dict, user_message: str) -> str:
    """
    将操作结果转化为自然语言回复
    实现策略：
      - 结构化数据优先使用本地模板（响应快、可控）
      - 复杂/开放式问题使用LLM生成回复
    """

def call_llm(prompt: str, context: List[dict] = None) -> str:
    """
    调用外部大语言模型API（OpenAI/Claude/国内模型）
    包含：请求重试、超时处理、Token限制、Fallback降级逻辑
    """
```

| MOD-ROOM | MOD-RESV | `cancel_future_reservations_by_room(room_id)` | 注销自习室时取消未来预约 |
| MOD-ROOM | MOD-RESV | `cancel_future_reservations_by_seat(seat_id)` | 注销座位时取消未来预约 |

| MOD-AI | MOD-ROOM | `list_rooms(...)` | 查询自习室列表 |

## 7. 数据传输对象（DTO）定义

DTO（Data Transfer Object）用于模块间传递结构化数据，避免直接暴露内部模型。

### 7.1 MOD-USER DTO

```python
# domain/user/dto.py
from dataclasses import dataclass
from typing import Optional, List

@dataclass
class UserDTO:
    id: int
    username: str
    name: str
    user_type: str
    department: Optional[str] = None
    email: Optional[str] = None

@dataclass
class UserProfileDTO:
    id: int
    username: str
    name: str
    department: Optional[str]
    email: Optional[str]
    active_reservations: int
    total_violations: int

@dataclass
class RoleDTO:
    id: int
    name: str
    description: Optional[str] = None

@dataclass
class RoleDetailDTO:
    id: int
    name: str
    description: Optional[str]
    permissions: List['PermissionDTO']

@dataclass
class PermissionDTO:
    id: int

    description: Optional[str]

    pages: int
```
