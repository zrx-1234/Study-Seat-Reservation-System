# 自习座位预约系统 - 数据库设计文档

## 1. 文档概述

### 1.1 目的
本文档描述自习座位预约系统的数据库设计，包括实体定义、表结构、字段说明、关联关系及约束规则，为开发、测试和维护提供数据层依据。

### 1.2 适用范围
覆盖学生端、管理端、AI 助手模块所需的所有核心业务数据。

### 1.3 设计原则
- 统一用户模型：学生和管理员共用 `user` 表，通过 `user_type` 区分。
- RBAC 权限体系：角色与权限多对多关联，支持灵活的权限控制。
- 状态驱动：预约、座位、自习室等均通过状态字段驱动业务流程。
- 可扩展性：系统配置采用键值对存储，支持运行时动态调整参数。

## 3. 数据表详细设计

### 3.1 用户与权限模块

#### 3.1.1 `user` - 用户表
存储学生和管理员的基础信息。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INT | PK, AUTO_INCREMENT | 主键 |
| `username` | VARCHAR(64) | UNIQUE, NOT NULL | 学号/工号/账号 |
| `password_hash` | VARCHAR(256) | NOT NULL | 密码哈希值 |
| `name` | VARCHAR(64) | NOT NULL | 真实姓名 |
| `user_type` | ENUM | NOT NULL | `student` 或 `admin` |
| `department` | VARCHAR(128) | NULL | 所属院系 |
| `email` | VARCHAR(128) | NULL | 邮箱 |
| `phone` | VARCHAR(32) | NULL | 电话 |
| `is_active` | BOOLEAN | DEFAULT TRUE | 账号是否启用 |
| `created_at` | DATETIME | DEFAULT NOW | 创建时间 |
| `updated_at` | DATETIME | DEFAULT NOW, ON UPDATE | 更新时间 |

#### 3.1.2 `role` - 角色表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INT | PK, AUTO_INCREMENT | 主键 |
| `name` | VARCHAR(64) | UNIQUE, NOT NULL | 角色名称（如 super_admin） |
| `description` | VARCHAR(256) | NULL | 角色描述 |
| `created_at` | DATETIME | DEFAULT NOW | 创建时间 |

#### 3.1.3 `permission` - 权限表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INT | PK, AUTO_INCREMENT | 主键 |
| `name` | VARCHAR(64) | UNIQUE, NOT NULL | 权限名称（如 用户管理） |
| `code` | VARCHAR(64) | UNIQUE, NOT NULL | 权限代码（如 user:manage） |
| `description` | VARCHAR(256) | NULL | 权限描述 |
| `created_at` | DATETIME | DEFAULT NOW | 创建时间 |

#### 3.1.4 `user_roles` - 用户角色关联表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `user_id` | INT | PK, FK → user.id | 用户 ID |
| `role_id` | INT | PK, FK → role.id | 角色 ID |

#### 3.1.5 `role_permissions` - 角色权限关联表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `role_id` | INT | PK, FK → role.id | 角色 ID |
| `permission_id` | INT | PK, FK → permission.id | 权限 ID |

### 3.2 自习室与座位模块

#### 3.2.1 `study_room` - 自习室表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INT | PK, AUTO_INCREMENT | 主键 |
| `name` | VARCHAR(128) | NOT NULL | 自习室名称 |
| `location` | VARCHAR(256) | NULL | 具体位置 |
| `capacity` | INT | DEFAULT 0 | 容纳人数/座位数 |
| `room_type` | ENUM | DEFAULT 'public' | `public`=全校公共, `department`=院系专属 |
| `department` | VARCHAR(128) | NULL | 院系专属时填写 |
| `open_time` | TIME | DEFAULT '07:00:00' | 每日开放起始时间 |
| `close_time` | TIME | DEFAULT '22:00:00' | 每日关闭时间 |
| `is_active` | BOOLEAN | DEFAULT TRUE | 是否可用（注销则为 FALSE） |
| `created_at` | DATETIME | DEFAULT NOW | 创建时间 |
| `updated_at` | DATETIME | DEFAULT NOW, ON UPDATE | 更新时间 |

#### 3.2.2 `seat` - 座位表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INT | PK, AUTO_INCREMENT | 主键 |
| `room_id` | INT | FK → study_room.id, NOT NULL | 所属自习室 ID |
| `seat_number` | VARCHAR(32) | NOT NULL | 座位编号 |
| `has_window` | BOOLEAN | DEFAULT FALSE | 是否靠窗 |
| `has_plug` | BOOLEAN | DEFAULT FALSE | 是否有插座 |
| `status` | ENUM | DEFAULT 'available' | `available`/`maintenance`/`retired` |
| `created_at` | DATETIME | DEFAULT NOW | 创建时间 |
| `updated_at` | DATETIME | DEFAULT NOW, ON UPDATE | 更新时间 |

**约束**：`UNIQUE (room_id, seat_number)` — 同一自习室内座位编号唯一。

### 3.3 预约与违约模块

#### 3.3.1 `reservation` - 预约记录表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INT | PK, AUTO_INCREMENT | 主键 |
| `user_id` | INT | FK → user.id, NOT NULL | 预约人 ID |
| `seat_id` | INT | FK → seat.id, NOT NULL | 预约座位 ID |
| `start_time` | DATETIME | NOT NULL | 预约开始时间 |
| `end_time` | DATETIME | NOT NULL | 预约结束时间 |
| `status` | ENUM | DEFAULT 'reserved' | 见下状态说明 |
| `check_in_time` | DATETIME | NULL | 实际签到时间 |
| `cancelled_by` | ENUM | NULL | `user`/`admin`/`system` |
| `cancel_reason` | VARCHAR(256) | NULL | 取消原因 |
| `created_at` | DATETIME | DEFAULT NOW | 创建时间 |
| `updated_at` | DATETIME | DEFAULT NOW, ON UPDATE | 更新时间 |

**预约状态说明**：
- `reserved`：已预约，未签到
- `checked_in`：已签到
- `completed`：正常结束
- `cancelled`：已取消（用户或管理员手动取消）
- `violation`：违约（超时未签到被系统自动取消）

#### 3.3.2 `violation_record` - 违约记录表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INT | PK, AUTO_INCREMENT | 主键 |
| `user_id` | INT | FK → user.id, NOT NULL | 违约学生 ID |
| `reservation_id` | INT | FK → reservation.id, UNIQUE | 关联的预约记录（一对一） |
| `violation_time` | DATETIME | NOT NULL | 违约发生时间 |
| `reason` | VARCHAR(256) | DEFAULT '超时未签到' | 违约原因 |
| `created_at` | DATETIME | DEFAULT NOW | 创建时间 |

### 3.4 签到与通知模块

#### 3.4.1 `sign_in_code` - 动态签到码表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INT | PK, AUTO_INCREMENT | 主键 |
| `room_id` | INT | FK → study_room.id, NOT NULL | 所属自习室 ID |
| `code` | VARCHAR(64) | NOT NULL | 动态编码或二维码字符串 |
| `valid_date` | DATE | NOT NULL | 有效日期 |
| `created_at` | DATETIME | DEFAULT NOW | 创建时间 |
| `expires_at` | DATETIME | NOT NULL | 过期时间 |

**约束**：`UNIQUE (room_id, valid_date)` — 每个教室每天只有一个有效签到码。

#### 3.4.2 `notification` - 通知表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| `id` | INT | PK, AUTO_INCREMENT | 主键 |
| `user_id` | INT | FK → user.id, NOT NULL | 接收人 ID |
| `type` | ENUM | NOT NULL | 见下通知类型说明 |
| `content` | TEXT | NOT NULL | 通知内容 |
| `is_read` | BOOLEAN | DEFAULT FALSE | 是否已读 |
| `created_at` | DATETIME | DEFAULT NOW | 创建时间 |

**通知类型说明**：
- `remind`：预约前提醒
- `check_in_alert`：签到提醒（预约后 10 分钟未签到）
- `violation`：违约通知
- `cancel`：预约取消通知
- `system`：系统通知

## 4. 核心实体关系

| 关系 | 类型 | 说明 |
|------|------|------|
| `User` ↔ `Role` | N:M | 一个用户可拥有多个角色，一个角色可分配给多个用户 |
| `Role` ↔ `Permission` | N:M | 一个角色可包含多个权限，一个权限可属于多个角色 |
| `StudyRoom` → `Seat` | 1:N | 一个自习室包含多个座位 |
| `User` → `Reservation` | 1:N | 一个学生可有多条预约记录 |
| `Seat` → `Reservation` | 1:N | 一个座位可被多次预约 |
| `Reservation` → `ViolationRecord` | 1:1 | 一条违约记录对应一条预约记录 |
| `StudyRoom` → `SignInCode` | 1:N | 一个自习室每天有一条签到码记录 |
| `User` → `Notification` | 1:N | 一个学生可接收多条通知 |

## 5. 索引与约束汇总

| 表名 | 约束/索引 | 说明 |
|------|-----------|------|
| `user` | UNIQUE (`username`) | 账号唯一 |
| `role` | UNIQUE (`name`) | 角色名唯一 |
| `permission` | UNIQUE (`name`), UNIQUE (`code`) | 权限名和代码均唯一 |
| `user_roles` | PK (`user_id`, `role_id`) | 联合主键 |
| `role_permissions` | PK (`role_id`, `permission_id`) | 联合主键 |
| `seat` | UNIQUE (`room_id`, `seat_number`) | 同一自习室座位编号唯一 |
| `violation_record` | UNIQUE (`reservation_id`) | 一条预约仅对应一条违约记录 |
| `sign_in_code` | UNIQUE (`room_id`, `valid_date`) | 每个教室每天仅一个签到码 |
| `system_config` | UNIQUE (`config_key`) | 配置键唯一 |

## 6. 设计决策说明

### 6.1 为什么学生和管理员共用 `user` 表？
简化数据模型，避免重复字段。通过 `user_type` 区分身份，配合 RBAC 角色实现权限控制。管理端用户绑定 `Role`，学生端用户不绑定角色。

### 6.2 为什么 `reservation` 和 `violation_record` 分离？
违约记录需要额外字段（如 `violation_time`、`reason`），且未来可能扩展惩罚策略。独立成表便于统计分析和灵活扩展。

### 6.3 为什么系统配置使用键值对？
管理端需要动态调整参数（US-A11）。键值对表无需修改表结构即可新增配置项，支持运行时热更新。

### 6.4 为什么 `sign_in_code` 按天存储？
需求要求动态编码/二维码每日与教室关联并更新。通过 `valid_date` 和联合唯一约束，天然保证每天每教室只有一个有效码，同时保留历史记录可追溯。
